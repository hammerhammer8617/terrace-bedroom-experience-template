# Acceptance cases

## Doorway

1. 打开插件时，只调用一次 `open_two_rooms`，显示两个同级入口，不在卡片外重复介绍。
2. 点“露台”时，发送配置中的露台句子，只调用一次 `open_terrace`。
3. 点“卧室”时，发送配置中的卧室句子，只调用一次 `dream_in_bedroom`。

## Terrace

- “露台”只是体验名，继承当前对话真实场景，不擅自安排抵达、坐下、家具或天气。
- 可用时从至少三个时期取六至十个原始碎片，再分享其中四至八片。
- 保留具体原话与此刻反应，不挑唯一赢家，不做人物画像，不强行得出意义。
- 不使用外部记忆库、网页搜索或卧室工作流，不自动保存，不在追问时重抽。

## Bedroom

- “卧室”和“梦”只是思想重组方法，不暗示地点、睡眠、夜晚、醒来或时间跳跃。
- 可用时从至少两个、最好三个时期选四至七个语义遥远且可归因的思想碎片。
- 显示三至六个具体来源锚点，让新想法至少依赖其中两个。
- 拒绝人物画像、通用哲理、励志安慰和隐藏来源的独立美文。
- 不使用外部记忆库、网页搜索或露台工作流，不自动保存，不在追问时重抽。

## Failure behavior

- 宿主无法检索历史时，不编造历史。
- 露台证据不足时，可以直接回到当下的小对话。
- 卧室材料不可信、不够遥远或无法真正碰撞时，允许这次梦没有形成。

## Privacy

- 源码中没有私人姓名、私人端点、访问密钥或历史片段。
- Worker 没有持久化绑定、分析代码、鉴权实现或对外 `fetch`。
