# Design notes

## 一句话模型

**露台让旧材料重新进入日子；卧室让遥远的旧材料第一次彼此相撞。**

两种体验都不是“记忆数据库”的另一层包装。数据库解决保存，露台与卧室解决重新相遇的方式。

## 露台：先捞一把，再产生反应

露台故意使用“哈哈”“等等”“其实”一类低信息词作为检索钩子。它们不替体验预先决定主题，因此更容易捞到琐碎、技术性、荒唐、未完成甚至当时毫无意义的旧片段。

关键不是随机选中一条，而是：

1. 先看见横跨多个时期的一整批原始碎片；
2. 保留四至八片，包括让人惊讶、困惑或无感的东西；
3. 把过去的原话与此刻的反应分开；
4. 不要求总结、意义或完整结尾。

## 卧室：可追溯的思想碰撞

卧室不是“根据用户画像写一篇哲理短文”。它从多个时期抽取四至七个语义遥远的思想碎片，再做跨域隐喻、尺度迁移、假设反转或错位问答。

一条新想法只有在以下条件成立时才算成功：

- 它至少因两个具体来源片段而发生；
- 删掉任一关键来源，结果会实质变化；
- 它没有被过去任何一方完整说过；
- 读者能看见来源残影与当下发明之间的边界。

## 为什么 Worker 不保存记忆

这份模板把 MCP 当作“门牌和方法交付层”，而不是记忆层。这样服务器无需接触私人聊天：

1. 用户显式选择一种体验；
2. Worker 返回一次随机、无身份的工作坐标；
3. 宿主在用户自己的上下文边界内查找旧对话；
4. 模型按照方法完成体验。

这也意味着跨平台能力取决于宿主是否能访问旧对话。MCP 本身不会突破宿主的权限。

## 可移植与不可移植

可以分享：取样规则、碰撞检验、失败行为、无状态 MCP、双入口 UI。

不应分享：私人称呼、真实聊天片段、个人服务器地址、账号 ID、访问凭据、记忆库路径，以及只对一段关系成立的语气指令。
